# ZOTA Smart (Home Assistant custom integration)

**Статус: в проде.** Нативная HA-интеграция `zota_smart` развёрнута и работает:
Home Assistant общается с LAN-модулем котла ZOTA PO Smart v2 напрямую, по
TLS-PSK на TCP-порту **1978**. MQTT-шлюз оставлен как откатный путь (остановлен
и disabled).

Эталонный котёл — **15 кВт, релейный**.

## Назначение

Управление котлом ZOTA PO Smart v2 напрямую, без облака ZOTA: Home Assistant
обращается к LAN-модулю котла по TCP-порту **1978** (TLS-PSK) или к локальному
шлюзу, и обменивается с ним плоскими кадрами
`<u16 link, u16 opcode, u16 len>` + payload.

Опция **«режим прокси»** в мастере настройки включает связь через **реальное
облако ZOTA** (`217.25.88.41:1978`) в режиме моста — котёл при этом остаётся
видимым для приложения ZOTA.

Протокол и все константы выверены по реверс-инжинирингу — см. комментарии
в `custom_components/zota_smart/const.py` (§11).

## Возможности

| Платформа | Сущности |
|---|---|
| `climate` | **Котёл** — пресеты по мощности котла из настроек, для 15 кВт — **Выкл / 5 / 10 / 15 кВт** (уставка-ограничитель) + уставка температуры **30–90 °C** |
| `switch` | **Насос 1** (`0x0A`: вкл `0x0101`, выкл `0x0102`) · **Насос 2** (`0x0B` raw: вкл `0b0000000000`, выкл `0b0001000000`) |
| `sensor` | **Датчик 1: помещение** · **Датчик 2: улица** · **Датчик 3: вода (подача)** · **Датчик 4: воздух** · **Встроенный датчик (колба)** · **Уставка** · **Ступень** (уставка) · **Мощность: текущая** (`[3]`×5) · **Мощность: уставка** (`[4]`×5) · **Ошибки** |
| `binary_sensor` | **Нагрев** (`[3]` > 0) · **Насос 1** · **Насос 2** |

## Требования

- **DNS override обязателен:** `control.zota.ru` → IP вашего Home Assistant
  (или IP локального шлюза). Без подмены DNS котёл продолжит ходить в
  родное облако ZOTA, и локальный канал работать не будет.
  Подменять нужно на уровне роутера/DNS-сервера (Pi-hole, AdGuard Home, `dnsmasq`).
- Home Assistant **2024.1+** (`manifest.json`, ключ `homeassistant`).
- Python-пакеты `cryptography` и `pyOpenSSL` входят в состав Home Assistant
  core, поэтому `requirements` в манифесте **пуст намеренно**: пиннинг версий
  в requirements HACS-интеграции привёл бы к даунгрейду системных пакетов HA.

## Установка

### Через HACS (custom repository)

1. В HACS открыть *Настройки → Репозитории → Добавить* и указать адрес
   этого репозитория (категория — *Custom integration*).
2. После добавления репозитория найти в HACS интеграцию **ZOTA Smart** и
   нажать **Установить**.
3. Перезапустить Home Assistant.

### Вручную

1. Скопировать каталог `custom_components/zota_smart` в
   `<config>/custom_components/zota_smart` вашего Home Assistant.
2. Перезапустить Home Assistant.

### Первый запуск

*Настройки → Устройства и службы → Добавить интеграцию → ZOTA Smart.*
В мастере указать имя котла, порт (по умолчанию 1978), **PSK модуля**,
мощность котла и при необходимости включить **«режим прокси»** + адрес облака.

## Получение PSK

PSK (pre-shared key) — это 32-байтовый ключ, общий у LAN-модуля котла и
родного облака ZOTA. В TLS-хендшейке (PSK-AES128-CBC-SHA256, identity
`Smart key`) он **не передаётся**: pre-shared key в TLS никогда не ходит по
сети и не подбирается — обе стороны просто знают его заранее. Поэтому
перехват TLS-трафика ключ не даёт.

Единственный источник ключа — **ресурсная секция прошивки платы индикации**:
32 байта PSK лежат в пакете прошивки, в контейнере ресурсов, сразу за
ASCII-маркером `"Smart key\0"`.

Как получить ключ **своего** котла:

1. Скачайте пакет прошивки **своей модели** с [zota.ru](https://zota.ru)
   (раздел с технической документацией):
   - **PO Smart v2** — пакет `PO_Smart_v2_*`, контейнер ресурсов `smart.zap`;
   - **MK-S / MK-S Plus** — пакет `ind_hw2_0_*` (внутри — свой контейнер
     ресурсов; имя может отличаться от `smart.zap`).
2. Найдите в пакете контейнер ресурсов (для Smart — `smart.zap`).
3. Расшифруйте контейнер: он XOR-обфусцирован (сетка 44-байтных записей,
   22-байтный ключ) и в открытом виде не содержит ни маркера, ни ключа.
   Из расшифрованного контейнера возьмите ресурсную секцию.
4. Найдите в расшифрованных данных ASCII-маркер `"Smart key\0"`
   (`53 6d 61 72 74 20 6b 65 79 00`). **Следующие 32 байта — это и есть
   PSK**; переведите их в hex — получится 64 символа. Это значение поля
   **«PSK модуля»**.

Шаг 4 автоматизирован утилитой `tools/extract_psk.py` (только стандартная
библиотека Python 3):

```bash
python3 tools/extract_psk.py путь/к/расшифрованному/контейнеру
```

Она ищет маркер во всех вхождениях и печатает смещение и следующие 32 байта
в hex. Если маркер не найден — выводит подсказку (файл, вероятно, ещё
зашифрован; ищите контейнер ресурсов в пакете прошивки). Сам ключ в репозитории
не хранится и в лог не пишется.

> Ключ, вероятно, **фабриальный для семейства**: в стандартной прошивке он
> один и тот же для всех котлов модели. Проверить это можно, подключив второй
> котёл с тем же ключом — если он подключится, значит, ключ общий.

Интеграция не логирует PSK: значение ключа не попадает ни в логи HA,
ни в stderr-диагностику моста.

## Настройка

Поля мастера (и перенастройки: запись → «Изменить параметры»):

| Поле | Обязательное | По умолчанию | Описание |
|---|---|---|---|
| Имя (`name`) | да | `Котёл` | Название котла в HA |
| Порт (`port`) | да | `1978` | TCP-порт LAN-модуля (TLS-PSK) |
| Режим PROXY (`proxy`) | да | выкл | Мост к родному облаку ZOTA |
| Адрес облака (`cloud_address`) | да | `217.25.88.41:1978` | Облако ZOTA в формате `host:port` |
| PSK модуля (`psk`) | да | — | TLS-PSK ключ: 64 hex-символа (32 байта). Как получить — см. «Получение PSK» |
| Мощность котла (`power_kw`) | да | `15` | 3–30 кВт, шаг 3. Определяет пресеты климата: **Выкл / P⁄3 / 2P⁄3 / P кВт** (15 → 5/10/15; 18 → 6/12/18) |
| Датчик текущей температуры (`temp_sensor`) | да | `Подача (датчик 3)` | Источник `current_temperature` climate-сущности: **Подача (датчик 3)** / **Встроенный датчик (колба)** / **Датчик 1: помещение** / **Датчик 2: улица**. Если выбранный датчик не подключён — climate показывает «нет данных» |
| Логировать кадры (`frame_log`) | да | выкл | Запись всех кадров (H2M/M2H/M2C/C2M) в `/config/zota_frames.log` для отладки протокола. **По умолчанию выключено**: лог растёт непрерывно; ротация — при 20 МБ текущий файл переименовывается в `.old` (перезапись). Включается/выключается в настройках записи без пересоздания |
| Серийник (`serial`) | нет | — | Серийник модуля (для будущего использования) |
| Пароль устройства (`device_password`) | нет | — | Пароль устройства (для будущего использования) |

Записи, созданные до появления поля `power_kw`, работают без изменений:
мощность по умолчанию — 15 кВт (пресеты Выкл/5/10/15 кВт не меняются).
Поле `psk` обязательно: если ключ не задан, интеграция не поднимется и
в интерфейсе появится сообщение **«Укажите PSK модуля в настройках
интеграции»** — укажите ключ через *«Изменить параметры»*. PSK нигде не
логируется.

## Совместимость

- **HAOS** и **Container** — поддерживаются.
- **pyOpenSSL не нужен** — TLS-PSK-сервер реализован на
  `cryptography` из состава HA core; внешних зависимостей нет
  (`requirements: []` в `manifest.json` — намеренно, см. «Требования»).

## Отладка

- Захват кадров — **опция** «Логировать кадры (отладка)» в настройках записи
  (`frame_log`, по умолчанию выключена): файл `/config/zota_frames.log`,
  ротация при 20 МБ (`→ .old`, перезапись). Кадры пишут координатор,
  TLS-сервер (H2M/M2H) и мост (M2C/C2M) — только при включённой опции.
- Логи интеграции: `docker logs homeassistant` (в HAOS — `ha core logs`).
- Мост и TLS-сервер пишут диагностику в **stderr** через `print(..., flush=True)`:
  Home Assistant **глушит INFO-уровень сторонних логгеров**, поэтому при
  отладке поднимать уровень логирования **WARNING** (и читать stderr).

## Дисклеймер

**Это экспериментальная интеграция.** Она управляет отопительным
оборудованием, и ошибка в её работе может привести к перегреву, замерзанию
контура или иным последствиям для системы отопления.

- Автор не несёт ответственности за любой ущерб, возникший в результате
  использования интеграции, включая повреждение оборудования и его
  компонентов.
- Перед использованием убедитесь, что система отопления спроектирована и
  обслуживается с учётом того, что управление идёт мимо штатного облака
  ZOTA, и что у вас есть независимый резервный способ управления котлом.
- Используйте интеграцию только с оборудованием, которым вы владеете или
  которым вам разрешено управлять.

Протокол ZOTA PO Smart v2 был восстановлен (реверс-инжиниринг) для
обеспечения совместимости с собственным оборудованием. Все права на

производителю. Данный проект не связан с ZOTA и не одобрен ею, не является
